# PROTOTYPE brief — 50 homepage redesigns for Kiln

Throwaway exploration. Each variant is a complete, single-page marketing homepage for Kiln with its own visual identity **and** its own marketing hypothesis (what to say, in what order, to whom). The user will cycle through all of them and pick the best, or combine pieces. Variety is the point: no two variants may share a layout concept, palette, type pairing or signature interaction. Earlier rounds, already seen and not to be repeated: a pottery-workshop parchment page (current site), an engineering-pad firing curve (A), a cobalt museum gallery of glazed vessels (B), a pink/blue risograph bookmark pile (C), and older studies (condensed-poster furnace, lavender commonplace book, midnight instrument console, branching green tree, blue desktop library window).

## What Kiln is — verified facts you may use

Kiln is a **Windows desktop app** (plus CLI, MIT licensed) for developers who use coding agents (Codex, Claude Code; Copilot for installs). Two big selling points, with nuance:

### Selling point 1 — your skills stop being loose folders: organised, visible, managed

- Today skills are folders scattered across `~/.claude/skills`, `~/.agents/skills` (shared by Codex, Copilot and others), `.codex/skills`, `.copilot/skills`, project `.github/skills`, plus prompts buried in chats, notes and bookmarks.
- Kiln keeps one **library**: prompts, skills, custom agent definitions (native Codex / Claude Code / Copilot formats), source notes, insights, techniques, tools and resources. Collections, search, tags, favorites, filters (kind, status, provider, location, copy state, scope, tag), bulk selection (Ctrl/Shift-click, Ctrl+A), archive, trash and restore, swipe-to-archive, undo.
- **Import** existing installed skills or a skills repository as drafts; originals stay where they are. "Find skills and agents not in the library" scans locations, and it offers safe cleanup of broken links and empty folders.
- **Visibility of copies:** for each skill, see every installed copy across personal locations and enrolled projects: installed, identical copy found, differs, linked, **edited outside Kiln (drift)**. Compare the installed copy file-by-file with the approved version. **Remove local copies** in bulk (managed copies deleted, others moved to private backups). Install receipts record revision and destination.
- **Token angle (phrase carefully):** every model-invoked skill's description sits in the agent's context on every turn, so forgotten, duplicate and stale skills spend tokens and attention whether or not they fire. Kiln shows you exactly what's installed where, so you can remove what you don't use and keep only what earns its place. Kiln's bundled "writing for agents" guidance (used when it drafts skills) is built around context load, pruning and descriptions that trigger well. Every test run shows its **token usage** (input / cached / output), model and reasoning effort. Kiln does **not** compute a per-skill token cost. Any per-skill token numbers you show must be visibly labelled as illustrative or sample.
- **Versions you can trust:** revision history and diffs; approval pins an **exact revision**; editing creates a new draft and never replaces the approved one; install always uses approved content. Approval commits and publishes that snapshot to **your own Kiln GitHub repository** (standard layout, validation that never executes skills). Git status, sync and conflict resolution are built in. Another machine: open the repo, press "Install everything marked for this machine" (`kiln skills sync`).
- **Config files editor:** CLAUDE.md, AGENTS.md, Codex config.toml and hooks.json, Claude settings, Copilot settings, MCP config, permissions, hooks, VS Code settings, shell profiles, all in one place. Edits happen in place, with syntax validation, 30 private backups, diff and restore, and stale-edit detection. Kiln never executes hooks.

### Selling point 2 — break the "I'll look at this later" loop: test it now, see results, learn prompting

- **Capture anything, fast:** paste or drop text, links, screenshots, images and files; tray icon; global quick search **Ctrl+Shift+Space**; Ctrl+N to capture. "Save only" keeps it without calling a model. "Analyze and add" turns a source into prompts, insights, techniques, tools and resources in a collection linked to the source.
- **YouTube distillation:** paste a link, press "Distill video". Captions become a collection of reusable entries with **timestamped source links**; the transcript stays attached.
- **Test it on your own repo, right away:** choose a local project or repository (or an isolated example), then run the exact prompt revision through Codex or Claude Code. You watch it live: messages, reasoning summaries, commands, web searches, model, reasoning effort, elapsed time and token counts. Up to two runs at once; cancel or retry. Experiments are **read-only**, so nothing in your code changes.
- **Immediate verdict:** output and the agent's **pass / fail / uncertain** assessment are saved against that revision. The agent's assessment is kept separate from **your** judgement: you decide what to keep. Tasks that need edits or unavailable tools come back as uncertain rather than faked successes.
- **Learn prompting by doing:** edit the prompt, compare revisions and diffs, and run it again on the same repo. You see what changed the result. "Ask the agent" discusses an item with its attachments and source-video context. "Create skill" drafts a SKILL.md from a prompt, image or note, using bundled writing-for-agents guidance, linked back to its source.
- **From prompt to habit:** a prompt that proves itself becomes a skill you approve and install into Codex, Claude Code or Copilot locations. A new agent session picks it up. The payoff: one tested prompt can change how you approach everyday AI work.

### Other facts

- Uses your **existing, signed-in Codex or Claude Code** (ChatGPT or Claude subscription). No API key, no extra API bill; subscription usage limits still apply. Normal editing, approval and installation never call a model.
- A consent notice explains what's sent before any agent interaction.
- The library lives locally and is backed by a GitHub repository Kiln creates for you (setup uses the official `gh` CLI). Not an offline or account-free product.
- CLI: script collections, items, experiments, approvals, installs; JSON results. Your agents can read your library through it.
- Download: Windows installer `https://github.com/waLLxAck/Kiln/releases/download/v0.17.0/Kiln.Setup.0.17.0.exe` (release 0.17.0). Say near the button that the release is hosted in a private GitHub repository and needs an account with access. Builds are unsigned (you may mention it in fine print).
- Real example prompts (condensed, from a real library) are in `../../content.ts` (`examples`), along with verified copy you may reuse or rewrite.

### Hard rules on claims

No testimonials, quotes attributed to people, user counts, star counts, logos of customers, benchmark numbers, percentages of improvement or "10x" claims. Illustrative numbers (a sample skills folder, a sample year, a sample receipt) must be visibly labelled as a sample or example. Don't claim macOS/Linux, remote deployment, automatic approval, per-skill token measurement, or that Kiln edits your code during tests. Humour and exaggeration aimed at the reader's own habits ("you saved 50 things") are fine as long as they aren't presented as data.

## Technical contract

- Folder: `apps/marketing/src/prototype/v/NN-slug/` (NN is your two-digit number, slug short kebab-case). Files:
  - `meta.ts`: `export const meta = { name: 'Short name', angle: 'One-line marketing hypothesis', focus: 'library' | 'testing' | 'both' } as const;` Only this, with no imports and no CSS.
  - `index.ts`: `import './style.css';` then `export function render(root: HTMLElement) { ... }`, which fills `root` (the `#app` div) with the page and binds interactions. Set `document.title`. ## Design rules

- Each page needs a hero, the story (in the order your angle dictates), real product detail from the facts above, at least one of the real example prompts or a faithful sample, and a download call to action with the private-repository note. Include as much of the nuance as your angle can carry; don't cram everything in.
- The concept is a starting point. Make it excellent: one memorable signature element (often the interaction or animation), with everything around it disciplined. Motion should answer the concept (a split-flap flip, a receipt printing, a brush stroke). Honor `prefers-reduced-motion`.
- Copy is half the experiment. Write a distinct voice and headline for your angle; don't reuse "From inspiration to an agent skill". Plain verbs, sentence case, specific, no filler, no fake urgency. Buttons say what happens.
- Avoid generated-page tells unless the concept demands them: tracked all-caps eyebrow labels above every heading, "A · B · C" meta strings, a lone italic or colored word in the headline, identical rounded cards with soft grey shadows, gradient washes as decoration, "→" on every link.
- Quality floor: responsive down to 390px (compose the phone layout deliberately; the signature element must survive), visible keyboard focus, real buttons and links, sufficient contrast, semantic headings, alt text or aria-labels for art.
